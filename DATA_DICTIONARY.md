# Data dictionary

All JSON and CSV files use UTF-8. Scores use the ordinal scale 0 (not addressed), 1 (partially addressed), and 2 (fully addressed).

## Evaluation results

Each `*_resolved.json` is an object mapping archived plan names to lists of successfully parsed evaluations. Each file covers 40 archived plan units. The study uses the 20 validation plans identified in `statistical_materials/configs/dataset_split.csv`; the files also retain records outside that subset.

| Model | Prompt | Parsed records across 40 plans |
|---|---|---:|
| GPT-4o | basic | 2203 |
| GPT-4o | optimized | 2238 |
| GPT-4o mini | basic | 2233 |
| GPT-4o mini | optimized | 2239 |

| Field | Type | Meaning |
|---|---|---|
| `Indicator` | string | Indicator name |
| `value` | integer | Archived human reference score |
| `Score` | integer | Parsed model score |
| `Reason` | array | Parsed scoring reasons |
| `Request` | string | Archived model input text |
| `Response` | string | Archived model response text |

Retrieval text-block collections, retrieval counts, and tool-call logs are excluded. Citations within model responses are retained. Missing evaluations are absent from these lists; they have not been assigned score 0. Filenames record run-start times; no timezone was encoded in the source filenames.

`evaluation_configurations.json` maps each model/prompt condition to its runner, result file, run start, and manuscript-reported settings. Current released calls enforce `temperature = 0` and `file_search.max_num_results = 20`. The latter is a retrieval cap. Complete historical run-level parameter metadata were not retained, so the current settings do not independently establish the historical settings.

## Indicator scoring-framework history

`optimization_history.json` is a list of 1095 records covering 56 indicators and 1034 distinct framework IDs.

| Field | Meaning |
|---|---|
| `Indicator` | Indicator name |
| `Framework_ID` | Archive identifier derived from the indicator name and framework text |
| `Father_Framework_ID` | Identifier for the parent framework, where recorded |
| `Scoring_Framework` | Framework text |
| `Interpretation_LLM` | Indicator interpretation text |
| `accuracy` | Archived agreement percentage, from 0 to 100 |
| `mean_squared_error` | Archived mean squared error on the 0–2 scale |
| `Evaluation_result_timestamp` | Archived evaluation timestamp, when available |

The same framework ID can appear in multiple records with different retained evaluation details. There are 183 records with one or more `null` fields, including 57 records containing parent-framework text with unavailable evaluation details. `null` preserves unavailable information; it is not a zero score. Parent IDs resolve within this file. The history does not contain retrieval text blocks or model-parameter metadata.

`scoring_framework&interpretation.json` maps 56 indicator names to the archived `Best_Scoring_Framework` and `Interpretation_LLM` text. `prompt.md` contains the shared prompt templates.

## Reference labels and statistical analysis

- `statistical_materials/data/human_reference_labels.csv`: 1400 rows, comprising 56 indicators for each of 5 development and 20 validation plans. The key is `(county, indicator)`.
- `statistical_materials/configs/dataset_split.csv`: the 25 retained plan assignments. No original randomization seed was recovered.
- `statistical_materials/data/validation_reference_labels.json` and `configs/validation_indicator_labels.csv`: the 1120 validation reference labels in two formats.
- `statistical_materials/data/predictions_long.csv`: 4480 planned validation evaluations, keyed by `(condition_id, county, indicator)`. Condition IDs are `gpt4o_basic`, `gpt4o_final`, `gpt4o_mini_basic`, and `gpt4o_mini_final`; `final` denotes the optimized prompt. Binary scores map 0 to absence and 1–2 to presence.
- `statistical_materials/configs/run_manifest_archived.csv`: condition/source mapping. Its paths are relative to `statistical_materials/`.
- `statistical_materials/configs/prediction_source_exceptions.csv`: three GPT-4o/basic scores supported by the original raw archive and retained in the prediction table, but absent from the shared resolved JSON.
- `statistical_materials/outputs/tables/`: ten CSV tables regenerated by `analysis/analyze_archived_results.py` from the included predictions and validation labels.

The prediction table contains 15 unavailable scores: 12 for GPT-4o/basic, 1 for GPT-4o/optimized, and 2 for GPT-4o mini/basic. Empty score cells indicate unavailable values; `score_parse_status` records their status. Of the 4465 available scores, 4462 match the shared resolved JSON and 3 are documented exceptions. Reference labels do not document the human audit procedure.

## Planning documents

The separate `Planning_documents_25_originals.zip` contains 5 development and 20 validation PDFs, plus `manifest.json` with each plan name, split, relative filename, byte size, and SHA-256 checksum. `statistical_materials/data/county_plan_inventory.csv` links the study plans to their archived source documents.
